# 1. How would you design a React application for a large-scale enterprise project?

For a large-scale React application, I would focus on separation of concerns, modular architecture, reusable components, efficient state management, performance optimization, and maintainability. The goal is to make the application easy to scale as more features and developers are added.

# 2. What is the difference between state, props, and context?

| Feature           | State                   | Props                            | Context                                    |
| ----------------- | ----------------------- | -------------------------------- | ------------------------------------------ |
| What is it?       | Component's own data    | Data passed from parent to child | Shared data across multiple components     |
| Mutable?          | ✅ Yes                  | ❌ No (read-only)                | ✅ Yes (via Provider)                      |
| Owned by          | Current component       | Parent component                 | Context Provider                           |
| Used for          | Component-specific data | Passing data                     | Avoiding prop drilling                     |
| Causes re-render? | Yes                     | Yes                              | Yes (consumers when context value changes) |

# 3. How do you prevent unnecessary re-renders in React?

## First, when does a React component re-render?

1. ✅ Its state changes
2. ✅ Its props change
3. ✅ Its parent re-renders (the child also renders by default)
4. ✅ The context value it consumes changes

## Ways to Prevent Unnecessary Re-renders

1. React.memo()

   Prevents a component from re-rendering if its props haven't changed.

2. useCallback()

   Functions are recreated on every render. With useCallback Now the function reference stays the same until its dependencies change.

3. useMemo()

   Memoizes expensive calculations.

# 4. When would you use useMemo() and useCallback()?

| `useMemo`                                       | `useCallback`                                   |
| ----------------------------------------------- | ----------------------------------------------- |
| Memoizes a **computed value**                   | Memoizes a **function**                         |
| Returns the result of a calculation             | Returns the same function reference             |
| Used for expensive computations                 | Used to prevent unnecessary function recreation |
| Returns any value (object, array, number, etc.) | Returns a function                              |

1. useMemo

   useMemo caches the result of a calculation and recomputes it only when its dependencies change.

2. useCallback()

   useCallback memoizes the function itself.

# 5. How do you handle API calls in React?

In React, I usually handle API calls inside the useEffect hook for data fetching on component mount or when dependencies change. I separate API logic into service files instead of calling APIs directly from components. While fetching data, I maintain loading, data, and error states to provide a good user experience. I also handle request cancellation using AbortController to avoid updating state after a component unmounts. In larger applications, I centralize API configuration using Axios with interceptors for authentication and error handling.

```js
import { useEffect, useState } from "react";

function Users() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    async function fetchUsers() {
      try {
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/users",
        );

        if (!response.ok) {
          throw new Error("Failed to fetch users");
        }

        const data = await response.json();
        setUsers(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }

    fetchUsers();
  }, []);

  if (loading) return <p>Loading...</p>;
  if (error) return <p>{error}</p>;

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```
