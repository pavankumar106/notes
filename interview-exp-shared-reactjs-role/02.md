# 1. state vs props

| Feature                  | State                                         | Props                                      |
| ------------------------ | --------------------------------------------- | ------------------------------------------ |
| **Definition**           | Data managed within a component               | Data passed from a parent component        |
| **Ownership**            | Owned by the component itself                 | Owned by the parent component              |
| **Mutable?**             | ✅ Yes (updated with `setState`/state setter) | ❌ No (read-only in the child)             |
| **Who Can Change It?**   | The component that owns the state             | Only the parent component                  |
| **Purpose**              | Store data that changes over time             | Pass data and behavior to child components |
| **Triggers Re-render?**  | Yes, when state changes                       | Yes, when prop values change               |
| **Initialization**       | Created using `useState()` or class state     | Received as function parameters or `props` |
| **Data Flow**            | Local to the component                        | One-way: Parent → Child                    |
| **Can Child Modify It?** | Only its own state                            | No, must request the parent to update it   |
| **Examples**             | Form input, counter, modal visibility         | User details, theme, callback functions    |

# 2. HTML vs React event handling

| Feature               | HTML Event Handling                             | React Event Handling                                                    |
| --------------------- | ----------------------------------------------- | ----------------------------------------------------------------------- |
| **Syntax**            | Uses HTML attributes                            | Uses JSX with camelCase                                                 |
| **Event Name**        | Lowercase (`onclick`)                           | CamelCase (`onClick`)                                                   |
| **Handler Value**     | String of JavaScript code                       | Function reference                                                      |
| **Prevent Default**   | `return false` or `event.preventDefault()`      | `event.preventDefault()`                                                |
| **Access Event**      | Global `event` (browser-dependent) or parameter | Event object passed to handler                                          |
| **Binding `this`**    | Not applicable                                  | Required in class components; not needed with function components/hooks |
| **Performance**       | Browser attaches handlers directly              | React uses its event system with delegated listeners                    |
| **Recommended Usage** | Small static pages                              | React applications                                                      |

# 3. What is "key" prop and what is the benefit of using it in arrays of elements?

A key is a special attribute you should include when mapping over arrays to render data. Key prop helps React identify which items have changed, are added, or are removed.

## Benefits of key:

- Enables React to efficiently update and re-render components.
- Prevents unnecessary re-renders by reusing components when possible.
- Helps maintain internal state of list items correctly.

# 4. What is Virtual DOM?

The Virtual DOM is a lightweight copy of the real DOM maintained in memory by React. When the application state changes, React creates a new Virtual DOM, compares it with the previous one using a process called reconciliation (or diffing), and updates only the changed elements in the real DOM. This minimizes expensive DOM operations and improves performance.

## Why Do We Need the Virtual DOM?

Updating the real DOM is relatively expensive because the browser may need to:

- Recalculate styles
- Perform layout (reflow)
- Repaint pixels
- Recompose the page

## Instead of updating the DOM on every change, React:

1. Updates the Virtual DOM in memory.
2. Compares it with the previous Virtual DOM.
3. Applies only the necessary changes to the real DOM.

How It Works

```
User Action
     │
     ▼
State Changes
     │
     ▼
New Virtual DOM Created
     │
     ▼
Compare with Previous Virtual DOM
(Reconciliation / Diffing)
     │
     ▼
Find Differences
     │
     ▼
Update Only Changed Nodes
     │
     ▼
Real DOM Updated

```

# 5. Virtual DOM vs Real DOM

| Virtual DOM                    | Real DOM                  |
| ------------------------------ | ------------------------- |
| Lightweight JavaScript objects | Actual browser DOM nodes  |
| Stored in memory               | Rendered by the browser   |
| Fast to create and compare     | Slower to update          |
| Compared using diffing         | Updated only when needed  |
| Controlled by React            | Controlled by the browser |

# 6. what are controllerd and non controlled components

Controlled Component: A form element whose value is controlled by React state using useState. Every change updates the state, and the UI reflects that state.

Uncontrolled Component: A form element that stores its own value in the DOM. React doesn't manage its state directly; instead, it accesses the value using a ref.

# 7. What are Higher-Order Components? give example

A Higher-Order Component (HOC) is a function that takes a component as input and returns a new component with additional functionality.

A HOC does not modify the original component. Instead, it wraps the component and enhances its behavior.

```js
function Home() {
  return <h2>Home Page</h2>;
}

function Dashboard() {
  return <h2>Dashboard</h2>;
}
function withLogger(WrappedComponent) {
  return function EnhancedComponent(props) {
    console.log(`${WrappedComponent.name} rendered`);

    return <WrappedComponent {...props} />;
  };
}

const HomeWithLogger = withLogger(Home);
const DashboardWithLogger = withLogger(Dashboard);
```

# 8. Stateful vs Stateless Components in React

| Feature            | Stateful Component                     | Stateless Component                    |
| ------------------ | -------------------------------------- | -------------------------------------- |
| **Definition**     | A component that manages its own state | A component that does not manage state |
| **Uses State?**    | ✅ Yes (`useState`, `useReducer`)      | ❌ No (or simply receives props)       |
| **Uses Props?**    | ✅ Yes                                 | ✅ Yes                                 |
| **Can Update UI?** | Yes, by updating its state             | Only when its props change             |
| **Purpose**        | Handles logic and dynamic data         | Displays UI based on props             |
| **Reusability**    | Usually less reusable                  | Usually more reusable                  |
| **Complexity**     | More complex                           | Simpler and easier to test             |
| **Examples**       | Forms, counters, modals                | Buttons, cards, headers, labels        |

# 9. How to apply validation on props in React?

Prop validation in React is commonly done using the prop-types library. It allows developers to specify the expected type of each prop and whether it is required. During development, React displays warnings if invalid props are passed, making components more reliable and easier to debug.

# 10. How do you memoize a component?

React.memo() is a Higher-Order Component that memoizes a functional component. React compares the previous and current props using a shallow comparison, and if they are the same, it skips re-rendering the component, improving performance.

```js
import React from "react";

const Child = React.memo(function Child() {
  console.log("Child rendered");

  return <h2>Child Component</h2>;
});
```

| Feature  | `React.memo()`                   | `useMemo()`              | `useCallback()`          |
| -------- | -------------------------------- | ------------------------ | ------------------------ |
| Memoizes | Component                        | Computed value           | Function                 |
| Prevents | Unnecessary component re-renders | Expensive recalculations | Function recreation      |
| Used For | Child components                 | Values                   | Event handlers/functions |

# 11. What are React Hooks?

React Hooks are built-in functions that let function components use state, lifecycle features, context, refs, and other React capabilities. They make code more reusable, readable, and easier to organize compared to class components.

1. useState()

   Used to store state in a component.

   ```js
   import { useState } from "react";

   function Counter() {
     const [count, setCount] = useState(0);

     return (
       <>
         <h2>{count}</h2>

         <button onClick={() => setCount(count + 1)}>Increment</button>
       </>
     );
   }
   ```

2. useEffect()

   Used for side effects.
   - API calls
   - Timers
   - Event listeners

   ```js
   import { useEffect } from "react";

   useEffect(() => {
     console.log("Component Mounted");
   }, []);
   ```

3. useContext()

   Access data from Context without prop drilling.

   ```js
   const theme = useContext(ThemeContext);
   ```

4. useRef()

   Stores mutable values and references DOM elements.

   ```js
   const inputRef = useRef();

   <input ref={inputRef} />;

   button.onClick = () => {
     inputRef.current.focus();
   };
   ```

5. useMemo()

   Memoizes expensive calculations.

   Without useMemo(), the calculation runs on every render.

   ```js
   const total = useMemo(() => {
     return calculateTotal(items);
   }, [items]);
   ```

6. useCallback()

   Memoizes functions.

   ```js
   const handleClick = useCallback(() => {
     console.log("Clicked");
   }, []);
   ```
