1.  ## What happens when state changes in React? Explain the render lifecycle.

    When state changes in `React`, it triggers a well defined render life cycle that determines what updates, when and how.

    At high level
    - state update is scheduled
    - React re renders the component
    - Reconciliation (diffing) happens
    - DOM updates are committed
    - Effects runs

    When state changes, React schedules an update, re-renders the component to produce a new virtual DOM, diffs it against the previous one, commits the minimal changes to the real DOM, and then runs side effects.

4.  ## What is code splitting? How do you implement it using React.lazy and Suspense?

    Code splitting is a performance optimization technique where you break your JavaScript bundle into smaller chunks and load them only when needed, instead of shipping the entire app upfront.

    This reduces initial load time, improves Time to Interactive (TTI), and is essential in production-scale React apps.

    ```js
    import { lazy, Suspense } from "react";

    const Dashboard = lazy(() => import("./Dashboard"));

    <Suspense fallback={<Loading />}>
      <Dashboard />
    </Suspense>;
    ```

5.  ## How does key prop work in lists? Why is index as key not recommended?

    The key prop helps React uniquely identify list elements during reconciliation. It allows React to match previous and next elements efficiently. Using the index as a key is discouraged because when items are reordered or removed, it can cause incorrect state preservation and UI bugs. Stable, unique IDs should always be used instead.

6.  ## What is the difference between var, let, and const (in terms of scope & hoisting)?

    var, let, and const differ mainly in scope, hoisting behavior, and reassignment rules.
    - var is function-scoped (or global if declared outside a function). It is hoisted and initialized to undefined, so it can be accessed before declaration without throwing an error.
    - let is block-scoped. It is hoisted but not initialized, so accessing it before declaration results in a ReferenceError due to the temporal dead zone.
    - const is also block-scoped and hoisted like let, but it must be initialized at declaration and cannot be reassigned. Accessing it before declaration also throws a ReferenceError.

9.  ## Explain shallow copy vs deep copy.

    Shallow Copy

    A shallow copy duplicates only the top-level properties of an object.
    If a property is a reference (object/array), both copies point to the same reference.

    ```js
    const original = { name: "Alex", address: { city: "NY" } };

    const shallow = { ...original };
    shallow.address.city = "LA";

    console.log(original.address.city); // "LA"
    ```

    Deep Copy

    A deep copy duplicates all levels of the object, creating independent references.

    ```js
    const deep = JSON.parse(JSON.stringify(original));
    deep.address.city = "SF";

    console.log(original.address.city); // "NY"
    ```

10. ## How does this work in arrow functions vs normal functions?

    Normal functions have a dynamic this based on how they’re called, while arrow functions lexically capture this from their surrounding scope and cannot rebind it.

    Normal Functions
    - Depends on how the function is called
    - Can change with .call(), .apply(), .bind()
    - In methods, this refers to the object before the dot

    Arrow Functions
    - Arrow functions do not have their own this.
    - this cannot be changed
    - .call(), .apply(), .bind() have no effect
    - Not suitable for methods

11. ## Implement debounce function in JavaScript.

    `Debouncing` ensures that a function is only executed after a certain delay has passed since the last time it was invoked.

    It’s commonly used for: - Search input - Window resize events - Scroll handlers - API calls

    ```js
    function debounce(fn, delay) {
      let id;

      return function (...args) {
        const context = this;

        clearTimeout(id);

        id = setTimeout(() => {
          fn.apply(context, args);
        }, delay);
      };
    }
    ```

13. ## Explain position properties (relative, absolute, fixed, sticky) with use cases.

    a. `position: relative`

    The element is positioned relative to its normal position in the document flow.
    - It still occupies space
    - You can move it using top, left, right, bottom
    - Often used as a reference for absolutely positioned children

    ```css
    .box {
      position: relative;
      top: 10px;
      left: 20px;
    }
    ```

    b. `position: absolute`

    The element is removed from normal flow and positioned relative to its nearest positioned ancestor

    If no positioned ancestor exists → it positions relative to the body.
    - Does not occupy space
    - Other elements ignore it

    Used In
    - Dropdown menus
    - Modals
    - Badges

    ```css
    .child {
      position: absolute;
      top: 0;
      right: 0;
    }
    ```

    c. `position: fixed`

    The element is positioned relative to the viewport, not any parent.
    - Removed from document flow
    - Stays fixed when scrolling

    Use cases
    - Sticky Navbar
    - Floating action button
    - Chat widget
    - cookie banner

    ```css
    .header {
      position: fixed;
      top: 0;
      width: 100%;
    }
    ```

    d. `position: sticky`

    Acts like relative until a scroll threshold is reached, then behaves like fixed.
    - Requires a scrollable parent
    - Needs top, bottom,...

    Use cases
    - Section headers that stick while scrolling
    - Sticky table headers
    - Sidebar navigation

    ```css
    .title {
      position: sticky;
      top: 0;
    }
    ```

## 16. Explain call, apply and bind

- call

  call() invokes a function immediately and allows you to pass arguments one by one.

- apply

  apply() is similar to call(), but arguments are passed as an array.

- bind

  bind() does not execute the function immediately.
  It returns a new function with this bound to the specified object.

```js
function greet(message) {
  console.log(message + " " + this.name);
}

var obj = {
  name: "Joe",
};

greet.call(obj, "Yo"); // Yo Joe

greet.apply(obj, ["Hey"]); // Hey Joe

var greet2 = greet.bind(obj, "Hi");
greet2(); // Hi Joe
```
