# 1. How do you prevent unnecessary renders in React?

The core idea: A component re-renders when its state, props,
or parent re-renders. You need to break those triggers selectively.

React.memo — skip re-renders if props haven't changed

useMemo — memoize expensive computed values

useCallback — stable function references for child components

Avoid inline objects/functions in JSX

# 2. How do you manage form state and errors?

I manage form state using controlled components with useState,
storing values and errors separately. I validate inputs on change or submit
and conditionally render error messages. For better UX, I track touched fields.

```js
function LoginForm() {
  const [values, setValues] = useState({ email: "", password: "" });
  const [errors, setErrors] = useState({});

  const validate = () => {
    const errs = {};
    if (!values.email.includes("@")) errs.email = "Invalid email";
    if (values.password.length < 6) errs.password = "Min 6 characters";
    return errs;
  };

  const handleChange = (e) => {
    const { name, value } = e.target;
    setValues((prev) => ({ ...prev, [name]: value }));
    setErrors((prev) => ({ ...prev, [name]: "" })); // Clear error on change
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    const errs = validate();
    if (Object.keys(errs).length) return setErrors(errs);
    // submit...
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="email" value={values.email} onChange={handleChange} />
      {errors.email && <span>{errors.email}</span>}

      <input
        name="password"
        type="password"
        value={values.password}
        onChange={handleChange}
      />
      {errors.password && <span>{errors.password}</span>}

      <button type="submit">Login</button>
    </form>
  );
}
```

# 3. Handling Loading, Error & Empty States in React

I manage separate state variables like loading, error, and data.
Based on these states, I conditionally render UI:

- Show loader while fetching
- Show error message on failure
- Show empty state if no data
- Otherwise render actual data

# 4. How do you optimize API calls

I reduce unnecessary API calls using debouncing and proper dependency management
in useEffect. I use caching libraries like React Query or SWR to avoid duplicate
requests and enable background updates. I also implement pagination or lazy loading
for large datasets, cancel stale requests using AbortController, and batch API
calls where possible. For better UX, I use prefetching and memoization when needed.

# 5.how do you handle controlled and uncontrolled behavior

Controlled components are managed by React state, where the input value is
driven by state and updated via onChange handlers. Uncontrolled components
rely on the DOM to manage their state, and we access values using refs.
Controlled components are preferred for complex forms and validation,
while uncontrolled components are useful for simple inputs or performance
optimization. In modern applications, libraries like React Hook Form use
uncontrolled inputs internally for better performance.

# 6. How will you structure state for scalability

I separate state into UI state, server state, and global app state.
I keep UI state local, use React Query for server state, and
Redux Toolkit for shared global state. I avoid duplication by normalizing data
and deriving computed values using selectors or useMemo.
I also follow a feature-based folder structure so each module manages its own state
and logic, which improves maintainability and scalability.

# 7. How will you manage open/close state cleanly

For simple cases, I use local state with useState. For scalability,
I avoid multiple boolean flags and instead use a single state like
activeModal or activePopup to track which component is open.
For reusable logic, I create custom hooks like useToggle.
If multiple components need access, I lift the state up or use Context/Redux.
This ensures predictable and maintainable state management.
